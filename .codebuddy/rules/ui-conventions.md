# MCard UI 强制约定

## 1. 移动端所有下拉必须使用底部弹窗（用户 2026-11-25 定稿，强制）

用户端 H5（`client/`）是移动端优先形态，网页原生 `<select>` 在手机上弹出的滚轮/下拉与整体体验割裂，**一律禁止**。

- **唯一实现**：`client/src/components/BottomSelect.vue`（触发项 + `BottomSheet` 底部弹窗选项列表，勾选后自动收起）。
- **用法**：`<BottomSelect v-model="xxx" :options="[{ value, label }]" title="选择…" />`；后台返回的 `[{key,label}]` 数据用 computed 映射成 `{value,label}`，不要在页面里另写弹层。
- **例外**：`client/src/views/Admin.vue` 是后台管理（桌面场景），保留原生 `<select>`；小程序 `miniapp/` 用原生 `<picker>`（本身就是底部弹层），也不在此约束内。
- **新增/改动任何移动端选择控件前先自查**：页面里不得出现 `<select>`。发版前用 `grep -R "<select" client/src/views` 核验，除 `Admin.vue` 外应为 0 命中。

## 2. 页面区块与操作分层（用户 2026-11-25 定稿，强制）

- 信息展示区只放信息（姓名/职位/标签/联系方式/简介/链接/二维码），不夹杂操作按钮与引导文案。
- 操作按钮（拨号/复制/收藏/分享/编辑等）统一收进底部 dock，不铺在内容区。
- 多步骤指引/确认只在弹层出现，页面任何位置都不常驻步骤说明。
- 内容块之间留足间距，底部留白 ≥ dock 高度。

## 3. 同模板同内容（用户 2026-11-25 定稿）

`/me`（持有者预览，CardView `owner` 模式）与公开名片页（`/c/:slug`）用同一套模板、同一套样式、同一屏内容；差异只在操作层：
- 持有者：dock = 编辑名片 / 配色风格 / 名片集市 / 分享，封面左上 `✎`。
- 公开页：dock = 打电话 / 复制号码 / 存入通讯录 / 分享，页面左上角透明竖签返回（竖排「集市/返回」，卡片外吸附，2026-11-28 定稿）。
- 不再有临时换肤圆点；配色由独立页 `/me/card/style` 正式保存。

## 4. 跨系统兼容（用户 2026-11-25 强调：不能顾此失彼）

构建基线：`client/vite.config.js` 的 `target:'es2018'` + `cssTarget:'chrome61'` 已让 Vite 转译新 JS 语法；但以下 CSS 不会被 cssTarget 降级，手写时必须自带兜底：

- **禁止 `inset:0`**（老微信 X5 / iOS WebView 不认，遮罩不铺满）→ 用 `top:0;right:0;bottom:0;left:0` 四边声明。
- **`color-mix()`** 只用于高亮/描边，前面必须先写一行纯色 fallback（如 `background:#eef4ff; background:color-mix(...)`），不支持时保留纯色。
- **`env(safe-area-inset-bottom)`** 必须写成 `padding-bottom: 10px; padding-bottom: calc(10px + env(...))` 两级，老内核不认 env 时保留第一级。
- **`overscroll-behavior:contain`** 不支持只是少一层滚动隔离，无害，可保留。
- 宽屏（PC 桌面壳 `@media(min-width:900px)`）下 fixed 底部条限宽 560px 居中，避免通栏横条。
- 小程序 `miniapp/` 保持 uni-app 原生、不用 web-view；H5 新写法不得破坏 PC 桌面壳与小程序原生三端。

## 5. 底部弹层层级（踩坑固化）

全局 tabbar（`MemberNav`）z-index 110。任何底部弹层必须：遮罩 120、弹层 121、常驻功能条 105（或统一用 `BottomSheet` 的 9999）；弹层加 `visibility:hidden` + `overscroll-behavior:contain` + 打开时锁 body 滚动，否则会出现「弹层被 tabbar 盖住点不到」「上拖带动背后页面」。

## 6. 独立设计页不叠 tabbar

`/me/card/style`、`/me/card/market` 自带底部功能条，`App.vue` 的 `hideMemberNav` 按路由隐藏全局 `MemberNav`；保存退出回 `/me` 后恢复。

## 7. 提示一律按当前功能口径（用户 2026-11-27 定稿，强制）

功能改过之后，用户可见提示（弹层/引导/表单说明/空态文案）必须按「现在能做什么」来写：

- 不得留旧口径：被移除/收敛的能力不要出现在提示里（如码点/码眼/中心 LOGO、vCard 文本码、登录态说明）。
- 不得写成变更史：「已移除 / 已固定 / 可自定义的只剩 / xx 定稿」这类话术不进提示；变更缘由只写在代码注释里。
- 多余的过程性废话直接删（反面教材：保存二维码引导里的「（已自动带上登录状态）/（无需登录）」）。
- 发版前自查：grep 提示文案里的「已移除/已固定/只剩/登录状态」等字样，命中即改写为当前口径。

## 8. 弹层能小就不大、操作直点不靠按钮（用户 2026-11-28 定稿，强制）

- 弹窗/底部弹层尺寸恪守「能小就不大」：内容一行排得下就排一行（多图并排、字段紧凑），不铺大面板。
- 图片类操作去按钮化：点缩略图本身即更换/上传，移除用缩略图右上角 × 小徽标（`ImageField.vue` 已统一此形态）；不再放「更换图片 / 移除」等旁挂按钮。
- 弹层内容与面板边缘留足内边距（≥16px），说明文字不得贴边通栏。
- 弹层视觉走轻奢去线条（用户 2026-11-28「线条多显得乱」）：分割靠留白与暖中性浅填充（如 #f5f3f0），不用描边/虚线/分割线；标题字距拉开，主按钮实心、次按钮纯文字，面板只留一处强调。
